\section{Methodology}\label{sec:method}

We conducted an observational repository-mining study. The workflow comprised four stages: selecting the AIDev challenge snapshot, enriching developer profiles with GitHub activity data, deriving activity-based experience profiles, and comparing agent use and pull-request outcomes across the resulting groups. The developer is the unit of analysis in all three research questions; for RQ3, pull-request-level comments are first aggregated within developers to avoid treating multiple contributions by the same person as independent observations.

\subsection{Data sources and sample construction}

We used the AIDev snapshot released for the MSR 2026 Mining Challenge \cite{li2026aidev}. The full-scope part of the snapshot contains 932,791 Agentic-PRs produced by five coding agents in 116,211 public GitHub repositories up to 1 August 2025 and links them to 72,189 developers. It provides pull-request metadata, repository information, and developer identifiers. Richer interaction data are available only for AIDev-pop, a curated subset of 33,596 Agentic-PRs from 2,807 repositories with more than 100 stars. In particular, issue-thread comments, formal reviews, inline review comments, commits, and related issues are limited to this subset. We therefore use the full-scope data for RQ1 and RQ2 and AIDev-pop for RQ3.

The activity visible in AIDev primarily describes developers in relation to agent-associated contributions. To obtain a broader activity profile, we enriched the developer records through the GitHub GraphQL API. Table~\ref{tab:profile-indicators} lists the 13 quantitative indicators used for clustering. The five-year indicators cover the five years preceding data collection. GitHub's restricted-contribution count was used as an indicator of private activity; because GitHub exposes only an aggregate selected by the account owner, this variable must not be interpreted as the exact number of private commits.

The GraphQL collection yielded activity records for 70,486 of the 72,189 developers (97.64\%). Numeric indicators for the remaining 1,703 developers were estimated using random-forest regression models \cite{breiman2001random}. The models were evaluated with an 80/20 train--test split, and predicted count values were rounded to integers. Their predictive performance was limited: the observed $R^2$ values were generally between 0.05 and 0.15 and were negative for some indicators. The imputed values should therefore be regarded as approximate coverage of missing profiles rather than reliable reconstructions of their activity.

\subsection{Preprocessing and activity-profile construction}

The indicators were strongly right-skewed and differed by several orders of magnitude. We first applied a quantile transformation toward a normal marginal distribution and then standardized every feature to zero mean and unit variance. We next used Isolation Forest with the contamination parameter set to 1\% to remove the most anomalous profiles \cite{liu2008isolation}. This procedure removed 722 developers and left 71,467 profiles for the primary analysis.

Principal component analysis (PCA) was applied to the transformed indicators to account for their correlations and obtain a lower-dimensional representation \cite{jolliffe2016principal}. The first two principal components retained approximately 95\% of the variance and served as input to the clustering algorithm. As shown in Figure~\ref{fig:pca-loadings}, the first component loaded positively on the activity indicators and was interpreted as a general-activity axis. The second component primarily contrasted repository visibility, represented by stars and forks, with direct contribution and review activity.

The two-component representation was partitioned using $k$-means clustering \cite{lloyd1982least}. We examined candidate solutions for $k=2,\ldots,10$ using average silhouette width \cite{rousseeuw1987silhouettes} and the gap statistic \cite{tibshirani2001gap}. Figure~\ref{fig:cluster-diagnostics} shows that neither diagnostic identifies $k=3$ as a unique numerical optimum: the largest observed silhouette value occurs at $k=9$, while the gap statistic continues to increase toward the upper end of the evaluated range. We nevertheless retained $k=3$ as a deliberately coarse and interpretable operationalization suited to comparisons among low-, intermediate-, and high-activity profiles. Thus, the analysis is conditional on this design choice and does not claim that three clusters constitute the intrinsic structure of the developer population.

The clusters were ordered by their positions on the general-activity component and by the corresponding values of the original indicators. For readability, we refer to the low-, intermediate-, and high-activity profiles as \emph{Junior}, \emph{Mid}, and \emph{Senior}, respectively. They contain 53,327, 16,192, and 1,948 developers. These names denote relative GitHub activity profiles within the analyzed population; they are not verified job titles, career stages, or direct measurements of programming competence.

\subsection{Outcome measures}

The three outcome variables were not included among the clustering inputs.

\paragraph{RQ1: AI-agent use intensity.}
For each developer, we counted the number of Agentic-PRs associated with that developer in the full AIDev snapshot. This variable measures observed contribution volume during the dataset window. It does not measure the proportion of the developer's total work performed with an agent or the general probability that the developer adopts AI tools.

\paragraph{RQ2: pull-request acceptance.}
For each developer, we calculated the proportion of resolved Agentic-PRs that were merged. A pull request was classified as merged when its \texttt{merged\_at} field was non-null and as rejected when it was closed without being merged. Open pull requests were excluded from the denominator rather than treated as rejected. Developers without a resolved Agentic-PR were excluded from this analysis. This outcome concerns acceptance of pull requests, not correctness of individual generated lines or overall code quality.

\paragraph{RQ3: review-discussion volume.}
Detailed discussion artifacts are not available in the full-scope tables, so this analysis is restricted to AIDev-pop. We use the \texttt{pr\_comments} table, which contains issue-thread comments associated with pull requests. Formal review records and inline review comments are not included in the primary measure. When a bot-authored pull request is linked to an issue, the issue creator is used as the human developer associated with the contribution, following the mapping rule used in the original analysis. Pull requests that cannot be mapped to one of the activity profiles are excluded.

For each retained Agentic-PR, we count non-bot comments written by an account other than the mapped developer; pull requests without a matching comment record receive a count of zero. The public AIDev fields do not provide a reproducible maintainer-role indicator for these commenters. We therefore interpret the outcome as \emph{external human discussion}, not as comments verified to have been written by maintainers. We aggregate the pull-request counts within each developer by computing the mean number of external comments per Agentic-PR. This avoids treating multiple contributions by the same developer as independent observations. The resulting measure is a proxy for visible discussion volume, not a direct count of requested corrections, review effort, defects, or code quality.

\subsection{Statistical analysis}

The outcome distributions were strongly non-normal, and the count-based measures contained many ties and zeros. For each research question, we first use the Kruskal--Wallis test to assess whether the outcome distributions differ across the three activity profiles. A significant omnibus result is followed by two-sided pairwise Mann--Whitney $U$ tests. The three pairwise comparisons within each research question are adjusted using the Bonferroni correction, with a family-wise significance level of $\alpha=0.05$.

For every group, we report the sample size, mean, standard deviation, and median. Because the large samples make very small differences statistically detectable, we accompany $p$-values with effect sizes: epsilon-squared for the Kruskal--Wallis test and rank-biserial correlation for pairwise comparisons. All analyses concern associations between activity-based profiles and observed outcomes; the observational design does not support causal claims about the effect of professional experience.
