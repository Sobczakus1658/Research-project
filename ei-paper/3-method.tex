\section{Methodology}\label{sec:method}

We conducted an observational repository-mining study. The workflow comprised four stages: selecting the AIDev challenge snapshot, enriching developer profiles with GitHub activity data, deriving activity-based experience profiles, and comparing agent use and pull-request outcomes across the resulting groups. The developer is the unit of analysis in all three research questions; pull-request-level outcomes are first aggregated within developers to avoid treating multiple contributions by the same person as independent observations.

\subsection{Data sources and sample construction}

We used the AIDev snapshot released for the MSR 2026 Mining Challenge \cite{li2026aidev} (Zenodo release v3, DOI \texttt{10.5281/zenodo.16919272}). The full-scope part of the snapshot contains 932,791 Agentic-PRs produced by five coding agents in 116,211 public GitHub repositories up to 1 August 2025 and links them to 72,189 developers. It provides pull-request metadata, repository information, and developer identifiers. All three research questions use this full-scope data.

The activity visible in AIDev primarily describes developers in relation to agent-associated contributions. To obtain a broader activity profile, we enriched the developer records through the GitHub GraphQL API. Table~\ref{tab:profile-indicators} lists the 12 quantitative indicators used for clustering. The five-year indicators cover the five years preceding data collection. GitHub's restricted-contribution count was used as an indicator of private activity; because GitHub exposes only an aggregate selected by the account owner, this variable must not be interpreted as the exact number of private commits.

For each developer, activity indicators were collected via a single GitHub GraphQL API v4 query per login, retrieving \texttt{followers}, \texttt{repositoriesContributedTo}, and yearly \texttt{contributionsCollection} aggregates (public commits, restricted contributions, pull-request reviews, and pull requests opened) for each of the five years preceding collection; because these are scalar aggregate fields rather than paginated connections, no pagination was required. Queries were issued sequentially with a 0.2-second delay per login using Python and the \texttt{requests} library. A login was recorded as unavailable -- covering deleted, renamed, and otherwise inaccessible accounts -- whenever the API returned a non-200 status, an error payload, or a null user, and such logins were skipped without retry; the corresponding developers are exactly the ones whose indicators were later estimated via random-forest imputation, described next. The GraphQL collection was run on 6 May 2026, roughly nine months after the AIDev snapshot's own 1 August 2025 cutoff; profile-level indicators such as followers, account tenure, and the yearly contribution aggregates therefore reflect each account's state as of the later collection date rather than the state at the time of the developer's Agentic-PRs, and may include activity that occurred after the snapshot window.

The GraphQL collection yielded activity records for 70,434 of the 72,189 developers (97.57\%). Numeric indicators for the remaining 1,755 developers were estimated using random-forest regression models \cite{breiman2001random}. The models were evaluated with an 80/20 train--test split, and predicted count values were rounded to integers. Their predictive performance was limited: the observed $R^2$ values were \texttt{collab\_breadth} 0.098, \texttt{5yr\_prs\_opened} 0.088, \texttt{5yr\_reviews\_given} 0.020, \texttt{5yr\_public\_commits} $-0.073$, and \texttt{5yr\_private\_work} $-0.272$. The imputed values should therefore be regarded as approximate coverage of missing profiles rather than reliable reconstructions of their activity.

\subsection{Preprocessing and activity-profile construction}

The indicators were strongly right-skewed and differed by several orders of magnitude. We applied a $\log(1+x)$ transformation and then standardized every feature to zero mean and unit variance. We next used Isolation Forest with the contamination parameter set to 1\% to remove the most anomalous profiles \cite{liu2008isolation}. This procedure removed 722 developers and left 71,467 profiles for the primary analysis.

A quantile transformation toward a normal marginal distribution was tried first in place of $\log(1+x)$, but a complete-case sensitivity check (Section~\ref{sec:threats}) found it unstable: clustering only the developers with real, non-imputed GraphQL data agreed with clustering the full population, on the same overlapping developers, at only Adjusted Rand Index $=0.46$. The same check with $\log(1+x)$ gave Adjusted Rand Index $=0.98$, so $\log(1+x)$ was adopted instead.

Principal component analysis (PCA) was computed on the transformed indicators to aid interpretation of the dominant axes of variation, not as a dimensionality-reduction step feeding the clustering algorithm \cite{jolliffe2016principal}: the first two principal components retain only approximately 50\% of the variance, so a 2-component projection would discard roughly half the signal. Clustering was therefore performed directly on the full 12-dimensional cleaned representation; PCA(2) is reported separately, purely to visualize which indicators drive the two dominant axes. As shown in Figure~\ref{fig:pca-loadings}, the first component loaded positively on the activity indicators and was interpreted as a general-activity axis. The second component contrasted agent-associated activity and public contribution volume (Agentic-PR activity span, Agentic-PR repository breadth, agent diversity, pull requests opened, and public commits) against general reputation and reviewing activity (followers, account tenure, maximum stars and forks, restricted activity, and reviews submitted).

The full 12-dimensional cleaned representation was partitioned using $k$-means clustering \cite{lloyd1982least}. We examined candidate solutions for $k=2,\ldots,10$ using average silhouette width \cite{rousseeuw1987silhouettes} and the gap statistic \cite{tibshirani2001gap}, computed on that same 12-dimensional representation. Figure~\ref{fig:cluster-diagnostics} shows that $k=3$ is not the numerical optimum on either diagnostic: silhouette width is highest at $k=2$ (0.332), decreases at $k=3$ (0.294), rises slightly at $k=4$ (0.302), and then declines further for larger $k$; the gap statistic increases roughly monotonically across the whole range and is highest at $k=10$ (2.58). We nevertheless retained $k=3$ as a deliberately coarse and interpretable operationalization suited to comparisons among low-, intermediate-, and high-activity profiles. Thus, the analysis is conditional on this design choice and does not claim that three clusters constitute the intrinsic structure of the developer population.

The clusters were ordered by the summed value of the 12 standardized indicators and by the corresponding values of the original indicators. For readability, we refer to the low-, intermediate-, and high-activity profiles as \emph{Junior}, \emph{Mid}, and \emph{Senior}, respectively. They contain 44,854, 12,705, and 13,908 developers. These names denote relative \emph{overall} GitHub activity profiles within the analyzed population -- the composite of all 12 indicators, not any single one -- and are not verified job titles, career stages, or direct measurements of programming competence. This distinction matters concretely for RQ1: the Mid profile turns out to have the highest median Agentic-PR count of the three (Section~\ref{sec:results}), even though it ranks below Senior on the composite activity score that names the clusters, because that score also reflects indicators (followers, account tenure, repository stars and forks) on which Senior scores higher.

\subsection{Outcome measures}

The outcome variables were not included among the clustering inputs.

\paragraph{RQ1: AI-agent use intensity.}
For each developer, we counted the number of Agentic-PRs associated with that developer in the full AIDev snapshot. This variable measures observed contribution volume during the dataset window. It does not measure the proportion of the developer's total work performed with an agent or the general probability that the developer adopts AI tools.

\paragraph{RQ2: pull-request acceptance.}
For each developer, we calculated the proportion of resolved Agentic-PRs that were merged. A pull request was classified as merged when its \texttt{merged\_at} field was non-null and as rejected when it was closed without being merged. Open pull requests were excluded from the denominator rather than treated as rejected. Developers without a resolved Agentic-PR were excluded from this analysis. This outcome concerns acceptance of pull requests, not correctness of individual generated lines or overall code quality.

\paragraph{RQ3: Agentic-PR acceptance vs.\ a human-authored baseline.}
AIDev separately provides \texttt{human\_pull\_request}, a baseline sample of human-authored pull requests (i.e.\ without agent involvement) drawn from repositories with more than 500 stars. We initially considered stratifying this comparison by the same Junior/Mid/Senior profiles used in RQ1--RQ2, but the two author populations overlap only marginally: of the 2,515 distinct authors in \texttt{human\_pull\_request}, only 351 also appear among the 72,189 developers linked to Agentic-PRs. RQ3 therefore compares two independent populations rather than matched individuals: the acceptance rate of all Agentic-PRs (as in RQ2, pooled across activity profiles) against the acceptance rate of \texttt{human\_pull\_request}, using the same merged/rejected/open-PR handling as RQ2. This is a population-level, not a developer-matched, comparison, and the human-authored baseline is itself restricted to a narrower, higher-star repository sample than the full Agentic-PR population.

\subsection{Statistical analysis}

The outcome distributions were strongly non-normal, and the count-based measures contained many ties and zeros. For RQ1--RQ2, each comparing three activity profiles, we first use the Kruskal--Wallis test to assess whether the outcome distributions differ across the three groups. A significant omnibus result is followed by two-sided pairwise Mann--Whitney $U$ tests, with the three pairwise comparisons per research question adjusted using the Bonferroni correction, at a family-wise significance level of $\alpha=0.05$. RQ3 compares only two independent groups (Agentic-PRs vs.\ the human-authored baseline), so a single two-sided Mann--Whitney $U$ test is used directly, without a Kruskal--Wallis omnibus step or a Bonferroni correction.

For every group, we report the sample size, mean, standard deviation, and median. Because the large samples make very small differences statistically detectable, we accompany $p$-values with effect sizes: epsilon-squared for the Kruskal--Wallis test and rank-biserial correlation for pairwise comparisons. Each effect size is reported with a 95\% confidence interval obtained by nonparametric bootstrap: for epsilon-squared, we resample each group independently with replacement, recompute the Kruskal--Wallis statistic, and take the 2.5th and 97.5th percentiles over 2,000 resamples; the same procedure, applied to the two groups being compared, is used for each pairwise rank-biserial correlation. All analyses concern associations between activity-based profiles and observed outcomes; the observational design does not support causal claims about the effect of professional experience.
