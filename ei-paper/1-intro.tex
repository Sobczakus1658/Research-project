\section{Introduction}\label{sec:introduction}

Large language models have changed AI support for software development from occasional code generation into an increasingly integrated part of the programming workflow. Early coding assistants mainly produced local suggestions within an integrated development environment. Studies of these tools showed both potential productivity benefits and the continuing importance of human judgment when interpreting, validating, and integrating generated code \cite{barke2023grounded,peng2023impact}. More recent AI coding agents operate at repository level: they can inspect project context, modify multiple files, execute development tools, and create complete \textit{pull requests}. This shift makes it necessary to study not only what agents can generate, but also how agent-associated contributions are used, reviewed, and accepted in real software projects \cite{li2026aidev}.

The human developer remains an important part of this process. Developers select or formulate tasks, provide context to an agent, assess its output, and respond to feedback during code review. These activities may differ across levels and forms of experience. Less experienced developers may use agents to compensate for limited familiarity with a codebase, whereas more experienced developers may be better able to delegate suitable tasks and evaluate generated changes. Conversely, highly active developers may use agents for more complex work, which could reduce acceptance rates or increase review discussion despite their greater experience. Thus, neither agent-use intensity nor contribution outcomes should be assumed to improve monotonically with developer experience.

Measuring developer experience from repository data is itself challenging. GitHub does not expose verified professional seniority, and observable activity is not equivalent to skill. Prior work has therefore represented developer expertise using multiple ecosystem-level signals rather than a single project-specific measure \cite{dey2021expertise}. In this study, we similarly treat experience as a multidimensional activity profile, not as a directly observed job title or career stage.

The closest prior study used the AIDev dataset to compare 22,953 agent-associated pull requests submitted by 1,719 developers divided into two experience groups according to their lifetime commit rate. It reported lower acceptance and substantially greater review volume for the lower-experience group \cite{asdaque2026novice}. These results establish that developer characteristics may matter in agent-supported development, but they also leave two questions open. First, it is unclear whether the same pattern appears when experience is represented using a broader set of activity signals and more than two groups. Second, that study focused on contribution magnitude and merge effort rather than on how intensively developers from different groups use coding agents.

We address these questions using the AIDev dataset released for the MSR 2026 Mining Challenge \cite{li2026aidev}. The challenge snapshot contains 932,791 agent-authored pull requests, referred to as \emph{Agentic-PRs}, produced by five coding agents across 116,211 public GitHub repositories and associated with 72,189 developers. We enrich these data through the GitHub GraphQL API with indicators such as account tenure, contribution breadth, public and private commits, code-review activity, repository ownership, and community recognition. We then use unsupervised clustering to derive three relative activity profiles. For readability, we call them \emph{Junior}, \emph{Mid}, and \emph{Senior}. These labels describe patterns in the analyzed GitHub data and must not be interpreted as verified professional positions or direct measurements of programming ability.

The study addresses the following research questions. We operationalize AI-agent use intensity as the number of Agentic-PRs per developer.

\begin{description}
    \item[\textbf{RQ1:}] How does AI-agent use intensity differ across the activity-based experience profiles?

    \item[\textbf{RQ2:}] How does the acceptance rate of Agentic-PRs differ across the activity-based experience profiles?

    \item[\textbf{RQ3:}] How does the acceptance rate of Agentic-PRs compare to that of human-authored pull requests from a comparably popular subset of repositories?
\end{description}

RQ3 differs from RQ1--RQ2 in scope: rather than comparing the three activity-based profiles against each other, it compares the full Agentic-PR population against an independent, non-agent baseline population, since the two populations of authors overlap only marginally (Section~\ref{sec:method}). All three questions concern statistical associations; the observational design does not support causal claims about the effect of experience or of agent use. After preprocessing, the analysis covers 71,467 developers. Their activity profiles are derived using \emph{k}-means clustering on the full set of standardized indicators, and group differences are evaluated using non-parametric statistical tests. The results do not reveal a simple low-to-high experience gradient: on the contrary, agent-use intensity is markedly \emph{non}-monotonic, with the intermediate-activity Mid profile submitting far more Agentic-PRs than either Junior or the highest-activity Senior profile, and acceptance rate is highest for Mid and lowest for Senior. Agentic-PRs are also accepted at a modestly higher rate than the human-authored baseline (RQ3).

This paper makes three contributions. First, it enriches AIDev with developer-level GitHub activity data and proposes a multidimensional operationalization of experience for a large population of coding-agent users. Second, it compares agent-use intensity and pull-request acceptance across three activity-based profiles, and contrasts agent-authored acceptance against an independent human-authored baseline. Third, it shows that the observed relationships are non-monotonic and differ from conclusions obtained under a narrower, binary operationalization of experience, highlighting the importance of measurement choices in empirical studies of human--agent collaboration.

The remainder of the paper reviews related work (Section \ref{sec:related}), describes the dataset and analytical procedure (Section \ref{sec:method}), reports the results for the three research questions (Section \ref{sec:results}), discusses threats to validity (Section \ref{sec:threats}), and concludes with implications for research and practice (Section \ref{sec:conclusions}).
